# Architecture

This vertical slice implements savings-balance retrieval against a local synthetic credit-union app. Gemini proposes one typed action from the current ARIA observation and successful action history. Python validates the proposal; a policy-constrained Playwright executor performs it. Discovery stops on verified outputs, failure, or a 12-step limit. The CLI accepts a goal and entry point but deliberately limits goal phrasings and requires the approved root page. This scope matches the workflow-specific verifier and compiler.

Discovery, compilation, and replay are separate phases. The compiler converts a successful record into a reusable capability; replay imports no planner and makes no model decisions. A dedicated wrapper demonstrates replay with planner/Gemini imports blocked and Gemini environment credentials removed. FastAPI supplies the test surface only: automation interacts with rendered controls rather than reading application data or calling a business API. Semantic locators avoid CSS layout coupling, but the implementation still depends on usable accessibility semantics. The target uses a shared styled layout while preserving the semantic headings, labels, and table structure used by automation. Normal replay and human handoff were verified after the styling changes.

# Artifact schema

A capability contains an ID/version, source run ID and SHA-256, typed string inputs, ordered actions, before/after page checkpoints, declared outputs, and a final success checkpoint. Inputs constrain the member ID to five ASCII digits. Targets identify exact labels, roles/names, or cells beside row headings. Outputs specify source targets and identity/literal/format checks. Money remains a decimal-formatted string rather than a binary float.

The compiler replaces observed member paths with `{member_id}` templates. It checks consecutive steps, supported paths, output fields, and recorded values; adjacent observations supply intermediate postconditions. It uses known page headings and the known workflow's output rules, so it is not a generic workflow synthesizer. Compilation validates serialization by round-tripping the typed artifact. The source hash provides provenance linkage, not authenticity, authorization, or proof that a run occurred. Public discovery evidence is a separately sanitized derivative; it is not a compiler input.

# Determinism & error handling

Replay validates inputs and policy, follows saved actions, and checks URL, heading, displayed identity, filled values, and final outputs. Target uniqueness and visibility use bounded assertions; ambiguous targets are not resolved by choosing the first match. Recoverable readiness waiting never repeats a submitted business action. “Deterministic” describes the decision path, not fixed timing or immunity to application changes.

Results distinguish success, a known member-not-found business outcome, and hard failure. Typed target errors report step, action, structural target kind, and observed match count. Operation events record starts, completion/failure, purpose, and elapsed time. Failures attempt a sanitized DOM capture before browser cleanup. Validation failures before browser creation explicitly report unavailable page evidence. Unexpected dialogs, permission errors, and session changes generally fail checkpoints; they do not yet have dedicated semantic classifiers.

Demonstrated runs include discovery for member 10002 followed by replay for 10001, normal replay, same-session human resume, transient target recovery (1.843 seconds), and bounded missing-target failure (5.007 seconds). After the UI changes, normal replay, human handoff, and all five evaluation cases passed. The evaluator checks statuses, outputs, exit codes, saved-output redaction, event persistence, and absence of unexpected handoff events. Discovery input-rejection reports were also verified. A deliberately injected planner exception, without a Gemini request, verified that discovery saves a sanitized DOM snapshot before browser cleanup and returns a structured failure with exit code 1. This fault-injection test is separate from the genuine successful Gemini discovery.

# Heterogeneity & multi-tenant

The proposed extension is a surface-adapter interface for observe, resolve, act, checkpoint, and sanitized evidence capture. Keep flow order and input/output rules independent of Playwright. Add discriminated target/checkpoint types for frame-scoped legacy web elements, OS accessibility controls, and bounded visual anchors. Screenshot/coordinate actions need resolution, window identity, scale, and postcondition checks; low-confidence targeting must stop rather than silently guess. These adapters are design work, not implemented support.

A shared vendor capability would declare product family, compatible versions, and a target/checkpoint profile. A tenant binding would supply approved origin, credential references, and reviewed locator/branding overrides. Overrides must not widen the tenant's policy or change output semantics without a versioned review. Run preflight checks and fixture replays per binding; quarantine incompatible bindings, preserve the previous approved version, and promote updates after review. Browser contexts, credentials, evidence access, and execution ownership would be isolated per tenant. The current prototype is single-tenant and has no registry or distributed execution service.

# Escalation & handoff

The known manual-review heading raises an intervention event with capability, goal, step, state, reason, timeout, and instructions. The headed browser and terminal form the operator interface. Ownership moves from automation to human, then to stopped during resume verification, then back to automation only after verification succeeds. Human checkbox/submission events are captured in the same session; no fresh browser is opened. Cancellation and timeout terminate control, and unused POST permission is revoked during cleanup.

This mechanism supports one known review gate rather than arbitrary discovery dead ends. A production operator queue would include run/session references, sanitized observations, authenticated operator assignment, and an exclusive ownership lease. Capture is limited to the known review controls; it is not a complete recording of every manual browser action. The terminal input thread is suitable for a short-lived CLI, not a reusable multi-session operator service.

# Safety

The configurable baseline permits one origin, approved routes/query keys, GET requests, and specific fill/click/read targets. Service workers and downloads are disabled in browser contexts; WebSockets and redirects are blocked. Guarded requests disable automatic retries. The browser guard is not an OS-level network sandbox and does not govern the separate Gemini SDK connection.

During human ownership, one form-encoded main-frame POST is permitted for the designated page and member URL with the expected Origin. Permission is consumed before sending, so unknown submission outcomes are not automatically retried. The server additionally checks an unexpired member-bound session, Origin, content type, a bounded form body, exact fields, acknowledgement, and a constant-time CSRF-token comparison. The server session lasts 600 seconds; handoff defaults to 180 seconds. Server approval lasts for that session, while the browser POST permission is single-use. Neither mechanism is real banking authorization. Cookies use HttpOnly and SameSite Strict; Secure is disabled for local HTTP. State is in memory and assumes one server process.

Only synthetic records are supported. Raw compilation records remain in ignored `runs/`; observations sent to Gemini can contain synthetic values. Public reports redact outputs, and DOM evidence omits attributes/tokens and unknown text. Replay console output shows synthetic values. These choices do not satisfy production PII handling: real deployment requires upstream data minimization, approved model/data boundaries, retention controls, and tested redaction. Risky financial actions remain unsupported rather than being inferred from this acknowledgement demo.

# Cuts

Desktop adapters, cross-tenant infrastructure, general operator escalation, production authentication, financial writes, a capability catalog, and model fallback during replay are intentionally omitted. Submission verification covers the implemented workflow and selected failure fixtures; it does not establish production readiness or exhaustive failure coverage. Further development would add artifact approval/version compatibility, per-stage discovery telemetry, and semantic classifiers for permission/session failures. Model explanations are not persisted: published decision context is explicitly a static action-purpose description. The prototype favors a reviewable end-to-end thread over broad workflow coverage.
